rain in wasm, in under 2k bytes

2026-08-24

I have been seeing a plethora of greptile comments on new PRs at work. So much so, I decided to have a nosey around their public github page. One of their core devs has this gem of a portfolio: soohoonchoi.com, and the animation inspired me so much, I wanted to take a stab at my own portfolio/blog.

So, here we are! The ascii rainfall you see on the homepage was handwritten in C, compiled to a sub-2k-byte wasm module, and rendered onto the page. I had a ton of fun coding this, and couldn't think of a better way to break in the new site than by explaining that code here.

rules first

As a challenge for this project, the code obeyed four important rules: no libc, no libm, no allocation, no globals. The caller hands over a single block of memory, and a macro sizes it at compile time. This also meant the terminal build could use a static buffer:

#define FIELD_BYTES(w, h)                          \
    ((size_t)(w) * (size_t)(h) * sizeof(float)     \
     + (size_t)(w) * sizeof(float)                 \
     + (size_t)(w) * sizeof(uint32_t)              \
     + (size_t)(w) * (size_t)(h))

Everything is flat buffers indexed y*w + x. Time arrives as a dt parameter. Input arrives as function calls.

the field

Each column is an independent stream of characters. A 32-bit hash of the column index gives it a permanent speed between 2.5 and 11 rows per second. A per-column accumulator collects speed * dt, and each time it crosses 1, the column shifts down one cell. Each cell gets multiplied by a decay factor so trails fade as they fall.

The char entering at the top of the screen comes from hashing the column and its shift count in blocks of eight. What's cool is that no state is getting stored for any of this: the rain is a pure function of (seed, column, shift count).

The cursor interaction (if you had even noticed!) is surprisingly the cheapest thing in the file. Moving the pointer rasterizes the segment since its last event with Bresenham and stamps zeroes in a small radius.

freestanding wasm

No emscripten (because why not?). The wasm build is clang --target=wasm32 -nostdlib, that's it, meaning we don't have any runtime at all. My custom allocator is just a bump pointer starting at the address the linker marks as the end of static data:

extern unsigned char __heap_base;

static void *balloc(size_t n)
{
    uintptr_t p = (next + 15u) & ~(uintptr_t)15u;
    uintptr_t end = p + n;
    size_t have = __builtin_wasm_memory_size(0) * PAGE;

    if (end > have) {
        size_t pages = (end - have + PAGE - 1) / PAGE;
        if (__builtin_wasm_memory_grow(0, pages) == (size_t)-1)
            return 0;
    }
    next = end;
    return (void *)p;
}

All in all, five exported functions: init, step, cut, chars, ramp. Compiled with -Oz and --strip-all, cutting the module down to 1755 bytes: smaller than most sites' favicons!!
